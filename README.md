# 旅行揪團活動系統

GitHub Pages 前端（純靜態）＋ Google Apps Script 後端（讀寫 Google Sheet、LINE 推播）＋ LIFF。

## 架構總覽

```
瀏覽器 / LINE App
   │  (fetch)
   ▼
GAS Web App（Code.gs，部署成 …/exec 網址）
   │  action=config / activities / waitlist（GET）
   │  action=joinWaitlist / notify / confirm / createActivity（POST）
   ▼
Google Sheet（activities 分頁、waitlist 分頁）
```

前端**只需要寫死一個網址**：GAS 部署後的 `/exec` 網址（`assets/main.js` 裡的 `CONFIG.API_BASE`）。
`LIFF_ID`、`SHEET_ID`、`GH_OWNER`、`GH_REPO` 都放在 **GAS 的指令碼屬性**，前端開頁時用
`action=config` 跟 GAS 要，不會出現在前端原始碼裡。

## 檔案結構
```
index.html            活動列表（登機證卡片），可勾選 2~5 個活動包成一則可滑動的訊息分享；
                       已核准的管理者會在最上方看到「新增活動／編輯活動／候補管理／管理申請」
detail.html           備註 + 行程 + 多個 YouTube/Google Map 連結（點擊才跳轉）+ 主辦人 LINE + 參加/候補
me.html               個人頁面：自己看過/參加/候補的活動清單（分現在/已過期），適合放進 LINE OA 的
                      Rich Menu 當獨立分頁；已核准的管理者也會在這裡看到管理選單
share.html            從 Flex 訊息的「分享活動」按鈕開啟，一鍵重新分享給其他好友/群組
confirm.html          候補者收到通知後，回覆「是否加入第 n 號活動」的 LIFF 頁（已回覆過/已逾期不會重複問）
admin/new-activity.html   管理者：新增活動表單（自動產生代碼、封面圖庫挑圖）
admin/edit-activity.html  管理者：編輯既有活動的所有欄位
admin/waitlist.html       管理者：候補名單管理，下拉選未過期活動、逐一發送 LINE 通知
admin/visit-log.html      管理者：閱讀記錄，時間軸列出誰打開/參加/候補/分享了哪個活動
admin/managers.html       管理者：審核「申請管理」名單，批准/拒絕（任何已核准管理者都能審核）
assets/main.js         共用邏輯：呼叫 GAS、LIFF 登入、Flex 產生器、多行欄位解析
assets/style.css
gas/Code.gs            貼到 Google Apps Script 專案的後端程式碼
```

> 所有 `admin/*.html` 頁面現在都用同一套邏輯保護：LINE 登入 → 確認這個 userId 是
> `managers` 分頁裡 `status=approved` 的人，不需要輸入任何密碼——每次打開頁面都會重新檢查一次身分。
> **沒有任何共用密碼**，包括審核其他管理者申請的 `admin/managers.html` 也一樣，只要是已核准的
> 管理者都能互相審核。

## 1. 建立 Google Sheet

建立一個試算表，含六個分頁（`activities`、`waitlist`、`managers`、`visits`、`cover-image`、
`organizer-presets`）。**除了 `cover-image`、`organizer-presets` 之外**，其他分頁都固定是這個結構：

- 第 1 列：程式讀取用的技術欄名（英文，例如 `id`、`title`，**不能改**，程式是用這一列比對欄位）
- 第 2 列：給人看的中文說明（自由填什麼都可以，程式完全不會讀這一列，純粹方便你自己看表）
- 第 3 列開始：實際資料

例如 `activities` 分頁前兩列長這樣：
```
id       title      cover_image   area   date_text  ...
活動代碼  活動名稱    封面圖網址     地區    日期文字    ...
trip001  鼻頭角...   https://...   新北市  8/8(六)    ...
```

### 分頁 `activities`
| 欄名 | 說明 |
|---|---|
| id | 活動代碼，唯一值 |
| title | 活動名稱 |
| cover_image | 封面圖網址 |
| area | 地區 |
| date_text | 日期文字（顯示給使用者看，格式自由） |
| event_date | 活動日期，格式 `yyyy-mm-dd`，**只用來判斷活動是否過期**，不會顯示在畫面上。留空則永遠視為「未過期」。`admin/waitlist.html` 的活動下拉選單只會列出未過期的活動。 |
| price | 價格 |
| capacity | 總名額 |
| joined | 已報名人數（GAS 會在候補者確認加入、或使用者按「參加活動」時自動 +1，其餘時候你可手動調整） |
| notes | 活動備註，顯示在詳情頁「行程」區塊之上，可留空，支援換行 |
| itinerary | **舊格式**，多天用 `\|\|` 分隔，只給還沒轉換的舊活動用，新活動不要填這欄 |
| days | 活動天數（1~10），決定詳情頁要顯示第幾天到第幾天的行程 |
| itinerary_day1 ~ itinerary_day10 | 每天各自一欄，換行就是斷行；每一行可以用 `文字\|網址` 的格式插入 YouTube/Google Map 連結（例如 `淡水漁人碼頭\|https://youtu.be/xxxx`），文字會變成可點擊的連結；如果只填網址、沒有文字，畫面會自動換成小圖示（YouTube 用 ▶️，Google Map 用 📍） |
| youtube_links | **可多行**，每行格式：`說明文字 YouTube連結`（順序、空白不拘），例如：<br>`行前說明會 https://youtu.be/aaaa`<br>`去年花絮 https://youtu.be/bbbb` |
| map_links | **可多行**，每行格式：`說明文字 Google地圖連結`，例如：<br>`集合地點 https://maps.app.goo.gl/xxxx`<br>`午餐地點 https://maps.app.goo.gl/yyyy` |
| organizer_name | 主辦人名稱 |
| organizer_line_url | 主辦人加好友連結，例如 `https://line.me/ti/p/xxxxxxx` |
| group_url | 揪團群組加入連結 |
| waitlist_status | 候補功能開關。**留空＝開放候補（預設）**，填 `closed` ＝關閉候補（額滿後不會出現「加入候補名單」按鈕） |

> 在 Google Sheet 儲存格內按 `Alt+Enter`（Mac 是 `Option+Return`）即可在同一格輸入多行文字。

### 分頁 `waitlist`
| 欄名 | 說明 |
|---|---|
| activityId | 對應 activities 的 id |
| userId | 候補者的 LINE userId（系統自動寫入） |
| displayName | 候補者的 LINE 顯示名稱 |
| status | `waiting` 排隊中／`notified` 已通知／`joined` 已加入／`cancelled` 已取消 |
| createdAt / notifiedAt / respondedAt | 時間戳記，系統自動寫入 |

這個分頁**不用手動建資料**，第 1、2 列照上面的規則填好（技術欄名 + 中文說明），第 3 列開始讓系統自己寫入即可。

### 分頁 `managers`
| 欄名 | 說明 |
|---|---|
| userId | 申請者的 LINE userId（系統自動寫入） |
| displayName | 申請者的 LINE 顯示名稱 |
| status | `pending` 待審核／`approved` 已核准／`rejected` 已拒絕 |
| appliedAt / decidedAt | 時間戳記，系統自動寫入 |

同樣把第 1、2 列填好（技術欄名 + 中文說明），資料從第 3 列開始由系統寫入。

### 分頁 `visits`（**事件流水帳，每次事件都新增一列，不是每人每活動一列**）
| 欄名 | 說明 |
|---|---|
| timestamp | 事件發生時間 |
| userId | 做這個動作的 LINE userId |
| displayName | 該使用者的 LINE 顯示名稱 |
| activityId | 對應 activities 的 id |
| action | `open`／`joined`／`waitlisted`／`shared`／`notified`／`confirm_open`／`waitlist_confirmed_join`／`waitlist_confirmed_cancel`／`waitlist_expired`（詳細意義見下方） |
| refUserId | 只有 `action=open` 且是點了「別人分享的連結」進來時才有值，是分享者的 userId |
| refDisplayName | 同上，是分享者的 LINE 顯示名稱 |

同樣是「技術欄名 + 中文說明」兩列表頭，資料從第 3 列開始，系統自動寫入，不用手動建資料。
這個分頁的資料可以在 `admin/visit-log.html`（閱讀記錄）看到整理過的時間軸，
或直接打開 Google Sheet 看原始資料。

### 分頁 `cover-image`（**例外：沒有表頭列**）
這個分頁**只有一欄（A 欄），從第 1 列開始，每一列放一個圖片網址**，不要加任何表頭或中文說明列，
例如：
```
https://i.meee.com.tw/ag3Eo9p.png
https://i.meee.com.tw/ZV1HBGI.png
https://i.meee.com.tw/0kfBVIV.png
...
```
`admin/new-activity.html` 開頁時會從這裡隨機挑 3 張當封面圖預覽小圖，點縮圖可以直接把網址帶入
「封面圖網址」欄位，也可以自己手動貼網址。

### 分頁 `organizer-presets`（**例外：沒有表頭列**）
這個分頁**只有 A、B 兩欄，從第 1 列開始**，A 欄放主辦人名稱、B 欄放對應的 LINE 加好友連結，
例如：
```
陳文清   https://line.me/ti/p/xxxxxxx
王小明   https://line.me/ti/p/yyyyyyy
```
`admin/new-activity.html` 的「主辦資訊」區塊會列出這裡的每一筆當作可點選的「常用主辦人」，
也可以在頁面上直接把目前填的名稱＋連結存成新的一筆常用。

以上分頁都不需要對外開放共用，因為現在資料完全透過 GAS 讀寫，不再用公開的 `gviz` 端點。

## 2. 建立 LINE Messaging API Channel（同時拿到 LIFF 與推播用的 Token）

1. [LINE Developers Console](https://developers.line.biz/console/) 建立 Provider。
2. 建立一個 **Messaging API** channel（會同時自動建立一個官方帳號 OA）。
3. 在該 channel 的 **LIFF** 分頁新增 LIFF app：
   - Endpoint URL：你的 GitHub Pages 根目錄，例如 `https://yourname.github.io/your-repo/`
   - **務必勾選「Share target picker」**
   - 記下 LIFF ID
4. 在該 channel 的 **Messaging API** 分頁，取得 **Channel access token（long-lived）**。
5. 建議把這個 OA 的加好友連結存起來，之後可以提醒候補者先加好友
   （LINE 規則：官方帳號只能推播訊息給已加好友、未封鎖的使用者）。

## 3. 部署 Google Apps Script

1. 到 [script.google.com](https://script.google.com) 新增專案，把 `gas/Code.gs` 的內容整個貼進去。
2. 左側「專案設定」→「指令碼屬性」，新增：

   | 屬性名稱 | 值 |
   |---|---|
   | LIFF_ID | 你的 LIFF ID |
   | SHEET_ID | Google Sheet 網址中 `/d/` 與 `/edit` 之間那段 |
   | GH_OWNER | 你的 GitHub 帳號名稱 |
   | GH_REPO | 你的 repo 名稱 |
   | CHANNEL_ACCESS_TOKEN | 上一步拿到的 Channel access token |
   | GH_BRANCH | GitHub Pages 部署的分支名稱，不設定預設是 `main` |
   | GH_TOKEN | GitHub fine-grained personal access token，**只給這一個 repo**、只勾 `Contents` 的讀寫權限。用來寫入一個很小的「活動最後更新時間」JSON 檔，不設定的話這個功能自動跳過，不影響活動本身能不能存檔 |

3. 右上角「部署」→「新增部署作業」→ 類型選 **網頁應用程式**：
   - 執行身分：我
   - 誰可以存取：任何人
4. 部署後複製產生的網址（結尾是 `/exec`）。

> 之後修改 `Code.gs` 記得「管理部署作業」→ 編輯 → 選新版本，網址才會套用新程式碼。

## 4. 設定前端 `assets/main.js`

只要改這一行：
```js
const CONFIG = {
  API_BASE: "貼上你的 GAS /exec 網址",
  MAX_SHARE_ITEMS: 5,
  MAX_CAROUSEL_BUBBLES: 12,
};
```

## 5. 部署到 GitHub Pages

```bash
git init
git add .
git commit -m "init"
git remote add origin https://github.com/yourname/your-repo.git
git push -u origin main
```
Repo 設定 → Pages → Source 選 `main` 分支根目錄。

## 6. 運作流程

### 一般使用者
1. 打開 `https://liff.line.me/{LIFF_ID}` → 自動登入 LINE，取得 userId。
2. 列表頁看活動、按「分享」單一分享，或勾選最多 5 個活動「分享所選」。
3. 進入活動詳情：系統會記錄「這個人打開過這個活動」（`visits` 分頁），看行程、多部影片
   （點了才跳轉到 YouTube，不是內嵌播放器）、多個地圖連結（一樣點了才跳轉，多筆並排顯示，
   超出寬度自動換行）。
4. 名額未滿 → 按「參加活動」，系統記錄 userId 並把 `joined` +1，成功後顯示「加入揪團群組」按鈕。
5. 名額已滿 → 按「加入候補名單」，寫入 `waitlist` 分頁（狀態 `waiting`）。

### 主辦人（候補通知流程）
1. 打開 `admin/waitlist.html` → 用 LINE 登入 → 系統確認這個 userId 是「已核准的管理者」就直接放行，
   不需要輸入任何密碼。
2. 下拉選單選活動（自動過濾掉已過期的）→ 看候補名單。
3. 有名額釋出時，點候補者旁邊的「傳 LINE 通知」：
   - GAS 把該筆狀態改成 `notified`
   - 推播一則 Flex 訊息，標題會加上活動日期，例如「8/8(六)｜鼻頭角公園浮潛」，並註明
     **請於 24 小時內回覆，逾時視為放棄名額**
   - 按鈕連到 `confirm.html?activityId=xxx`（LIFF 頁）
4. 候補者點按鈕 → 開啟 `confirm.html`：
   - 系統會先檢查是否已經回覆過（`joined`/`cancelled` 就直接顯示結果，不會重複問）
   - 也會檢查是否已經**逾 24 小時**（超過就顯示「已逾期」，不能再回覆）
   - 否則顯示「第 n 號活動：是否加入」+ 加入／取消 兩個按鈕：
     - 按**加入**：狀態改成 `joined`，活動 `joined` 人數 `+1`，顯示「加入揪團群組」按鈕
     - 按**取消**：狀態改成 `cancelled`，主辦人可以在候補清單中通知下一位

### 新增活動
1. 打開 `admin/new-activity.html`，一樣要 LINE 登入 + 已核准管理者身分，不需要輸入密碼。
2. 活動代碼會**自動產生**（`trip001`、`trip002`…依現有活動自動遞增），也可以自己改。
3. 「封面圖片」區塊會從 `cover-image` 分頁隨機挑 3 張當縮圖，點縮圖就把網址帶入
   「封面圖網址」欄位；不喜歡可以按「換一批」重新抽，或直接手動貼網址。
4. 填完送出，直接寫入 Google Sheet 的 `activities` 分頁一筆新資料，`joined` 預設為 0。

### 管理者申請（一般使用者 → 變成可以管理活動的人）
1. 一般使用者在 `index.html` 右上角按「申請管理」，確認後系統直接記錄 userId + 顯示名稱到
   `managers` 分頁，狀態為 `pending`，不需要設定任何密碼。
2. **任何一位已核准的管理者**都可以打開 `admin/managers.html`，看到申請名單，按「批准」或「拒絕」
   （不需要另外的擁有者密碼——只要你自己是 `approved` 狀態，就有審核別人的權限）。
3. 申請人只要之後重新整理 `index.html`，只要他還是登入同一個 LINE 帳號：
   - 已核准 → 最上方變成「新增活動／編輯活動／候補管理／閱讀記錄／管理申請」五個連結
   - 待審核 → 顯示「審核中」
   - 被拒絕 / 尚未申請 → 顯示「申請管理」按鈕
4. 已核准的管理者打開任何 `admin/*.html` 頁面時，系統都是用他自己的 userId 授權
   （GAS 端的 `requireApprovedManager()` 會檢查 `managers` 分頁裡這個 userId 是不是
   `approved`），**沒有密碼、PIN、或任何形式的登入憑證**，完全靠 LINE 登入身分。

> **「開國」怎麼辦？** 系統裡完全沒有共用的擁有者密碼了，所以第一個管理者沒辦法透過網頁
> 自己審核自己。你要做的事：打開 Google Sheet 的 `managers` 分頁，手動新增一列，
> `userId` 填你自己的 LINE userId（可以先在 `index.html` 按「申請管理」，系統會寫入一列
> `pending`，你再手動把那一列的 `status` 改成 `approved` 就好），之後你就能用
> `admin/managers.html` 審核其他人了。

### 新增活動 / 編輯活動
- `admin/new-activity.html`：活動代碼會**自動產生**（`trip001`、`trip002`…依現有活動自動遞增），
  也可以自己改；「封面圖片」區塊會從 `cover-image` 分頁隨機挑 3 張當縮圖，點縮圖就把網址帶入
  「封面圖網址」欄位，不喜歡可以按「換一批」重新抽，或直接手動貼網址。
- `admin/edit-activity.html`：下拉選一個既有活動，會把所有欄位（含備註、行程、影片/地圖連結）
  帶入表單讓你修改，儲存後直接覆蓋 Google Sheet 對應那一列（`id` 跟系統自動維護的 `joined`
  人數這兩欄不能透過這個頁面改）。

## 這次更新的重點（活動列表套用同一套快取／管理員檢查全面延後到閒置時段）

1. **`index.html`（活動列表）套用跟 `detail.html` 一樣的快取機制**：第一次打開打 GAS，
   之後重新整理直接用 `localStorage` 秒開；按「更新」時先讀 GitHub 上的版本檔，比對「所有
   活動裡最新的更新時間」有沒有比本地記住的新——沒有任何活動被更新過就直接顯示「已是最新，
   未重新讀取」，不會呼叫 GAS；只要有任一支活動被新增或編輯過，就會重新呼叫 GAS 抓最新列表。
2. **`index.html`、`detail.html` 的管理員權限檢查都改成排到瀏覽器閒置時段才執行**
   （`scheduleIdle()`，優先用 `requestIdleCallback`，不支援的環境退回 `setTimeout`）。
   一般使用者（非管理者）完全不會因為這個檢查等待，活動列表/活動詳情該多快就多快；
   只有背景驗證通過的管理者，才會在閒置時段之後看到管理功能出現（`index.html` 右上角的
   管理選單、`detail.html` 右下角的 ⚙️ 浮動按鈕）。

## 這次更新的重點（詳情頁快取改用「GitHub 版本檔比對」，GAS 快取改版本化）

1. **`detail.html` 重新加回快取，但這次多了一層「先問 GitHub 有沒有變」**：
   - 第一次打開會照常打 GAS，資料存進 `localStorage`，同時去讀 GitHub 上的一個很小的
     版本檔（`data/last-updated.json`），記住這筆活動當下的版本時間戳記。
   - 之後重新整理或再次打開，**直接用本地快取秒開**，不會自動打 GAS。
   - 按「更新」時：**先讀 GitHub 上的版本檔**（純靜態檔案，走 CDN，沒有 GAS 冷啟動），
     比對這個活動的時間戳記有沒有比本地記住的新——**沒有變動就直接顯示「已是最新，未重新
     讀取」，完全不會呼叫 GAS**；只有真的偵測到變動，才會呼叫 GAS 重新讀取完整資料。
2. **新增/編輯活動成功後，GAS 會把這個活動的最後更新時間寫進 GitHub 的
   `data/last-updated.json`**（best-effort，寫入失敗不影響活動本身有沒有存檔成功；
   沒設定 `GH_TOKEN` 的話這個動作會直接跳過）。
3. **GAS 端的 `CacheService` 共用快取改成「版本化 key」**：不再需要到處手動呼叫清快取的
   函式，資料一有變動（新增/編輯活動、參加、候補轉正）就呼叫 `bumpDataVersion()` 讓版本號
   往前推進，快取的 key 裡帶著版本號，版本一變，舊 key 自然變成讀不到（cache miss），
   下一次讀取會自動用新版本號重新讀 Sheet、存進新的快取 key，不用手動清除任何東西。
4. **閱讀記錄／分享／候補等行為記錄維持原樣，只存在 Google Sheets，不會額外複製一份到
   GitHub**——這類「誰、什麼時候、做了什麼」的稽核紀錄，寫入 GitHub 需要在前端暴露有寫入
   權限的 Token，等於任何人打開瀏覽器都能看到、拿去亂寫你的 repo，這個風險沒辦法用「輕量化」
   來規避，所以維持用 GAS 寫回 Sheet 這條路，而且這類記錄本來就是「不等待、背景執行」
   （fire-and-forget），不會拖慢頁面載入速度。

## 關於 LIFF 網址深層連結（重要更正）

`https://liff.line.me/{LIFF_ID}` 這個網址格式，官方文件列出的支援用法就只有這一種——**後面
不能接路徑**（例如 `/detail.html`）來指定要打開哪個頁面。如果在 liffId 後面加路徑或查詢字串，
LINE 會把你加的東西包進一個叫 `liff.state` 的參數，導去的仍然是你在 LINE Developers Console
設定的那個唯一 **Endpoint URL**，不會自動幫你跳轉到 `detail.html`、`confirm.html`、`me.html`
這些不同檔案。

所以這個專案裡，凡是要「打開特定頁面＋帶參數」的連結（分享出去的 Flex 訊息、候補通知推播、
Rich Menu 連結），一律用**純網址**（`assets/main.js` 的 `RUNTIME.siteUrl`／GAS 的
`siteUrl()`），不透過 `liff.line.me` 轉一手。純網址一樣可以在 LINE 裡用 LINE 內建瀏覽器打開，
頁面裡的 `liff.init()` 一樣會正常運作（登入、拿 profile、分享功能都不受影響），只是不會是
`liff.line.me` 開頭的網址而已。`https://liff.line.me/{LIFF_ID}`（不帶任何路徑/參數）只適合當
「唯一進入點」用，例如你自己要打開列表頁、或 Rich Menu 設定成 LIFF 類型指向首頁的情境。

   ```
   2026/7/19 14:20:11：江將 打開了 8/8(六) 鼻頭角公園浮潛 活動頁
   2026/7/19 14:22:00：江將 參加 8/8(六) 鼻頭角公園浮潛 活動頁
   2026/7/19 14:25:30：小明 打開了 江將 分享的 8/8(六) 鼻頭角公園浮潛 活動頁
   ```
   原理：分享活動時，Flex 訊息裡「活動詳情」按鈕的連結會偷偷帶上分享者的 userId/顯示名稱
   （`refId`/`refName` 這兩個網址參數），對方點開時 `detail.html` 會把這個資訊一起記錄下來，
   閱讀記錄頁就能顯示「是誰分享的」。這也連帶把 `visits` 分頁的資料結構從「每人每活動一列」
   改成「事件流水帳」（每次打開/參加/候補/分享都新增一列），細節看上面 Sheet 欄位說明。

## 關於「2~5 個活動一起分享」的做法

`liff.shareTargetPicker()` 這支 API 一次呼叫最多只能帶 **5 則訊息物件**；Flex Carousel 容器本身
則最多可放 **12 張 bubble 卡片**，這是兩個不同的限制。本專案選擇用 Carousel 的方式：
- 單一活動「分享」→ 送 1 則 flex 訊息（1 個 bubble）
- 列表頁勾選 2~5 個活動「分享所選」→ 包成**同一則** flex 訊息、裡面是一個 carousel（多個 bubble），
  收到的人可以左右滑動切換查看每個活動，而不是收到好幾則各自獨立的訊息。

## 之後可以擴充
- 候補名單目前需要主辦人手動點「傳 LINE 通知」，可以加一個「自動通知下一位」的按鈕，
  在有人取消候補、退團、或逾期放棄時自動觸發。
- 可以用 GAS 的時間觸發器（Triggers）定期掃描 `waitlist`，把逾期的 `notified` 主動標成
  `expired` 並通知主辦人「該找下一位候補了」，不用等主辦人或候補者剛好打開頁面才觸發判斷。
- 如果想幫忙看「誰打開過活動但沒有報名」，可以另外做一個小的 `visits` 檢視頁面，或直接用
  Google Sheet 的篩選功能看（現在已經有 `admin/visit-log.html` 可以看整理過的時間軸了）。
